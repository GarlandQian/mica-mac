# Workbench UI Contract

## Scope

Apply this contract to every visible Mica workbench surface, controller selector, toolbar command, same-window inspector, preference control, localization key, and source verifier change.

## Navigation And Window

- `WorkbenchDestination` is the only top-level presentation state: eleven destinations in fixed order — Overview, Proxies, Connections, Logs, Rules, Sources, Controllers, Configuration, Actions, Diagnostics, Settings — grouped in the sidebar as Workbench, Controller Management, and App Settings. There is no second-level segmented control inside the content area.
- Selection persists under the single `workbenchDestination` key. `migrateLegacyNavigationIfNeeded` maps the legacy `workbenchArea` + section keys (and the older single-string destination) to a destination once, with Overview as the safe fallback, and never overwrites an existing new-key value.
- The main window uses `NavigationSplitView`; the sidebar uses `List(selection:)` over the grouped destinations. Do not add an abstract Command menu or recreate selection with bespoke buttons.
- `⌘1` through `⌘6` select the six Workbench destinations through the standard View menu (`workbenchTabCases`); Controller Management and Settings destinations carry no number shortcut. The Controller menu contains Test, Refresh, Pause/Resume Presentation, Edit Current Controller, and Copy Diagnostics. Add belongs to File; Delete belongs to Controllers. Menu and toolbar actions share capability rules, and Refresh is disabled while presentation is paused.
- The sidebar renders destinations only. Controller count never changes sidebar geometry. A toolbar `Menu` shows the active controller in saved order (all at ten or fewer; current plus up to eight recent entries above ten) and exposes Manage/Add. Recent history updates from every explicit selected-controller change, not only toolbar menu actions, and never mutates saved controller order. The Controllers destination owns the complete management list.
- Controllers uses a native SwiftUI `Table`. Row selection is management selection only; explicit Use changes the live session. The table preserves manual persisted order, never sorts by name/status, shows complete selectable endpoints, and keeps Use/Test/Edit/Delete at the far trailing edge. Wide mode exposes seven columns; compact mode exposes equivalent Controller/Status/Actions composite columns without hiding business fields.
- Controller selection, endpoint presentation, inline policy/node actions, latency tests, and source updates stay inside the main window. Detail for connections, rules, and sources opens as an on-demand `.inspector` (opened by row selection, closed by clearing it) instead of a resident split placeholder. Fixed-selection cancellation stays inline in the expanded policy group and appears only when the controller exposes both a real fixed state and cancellation capability. Only destructive/high-risk actions may use a platform confirmation.

## Visual Hierarchy

- Native windows, sidebars, toolbars, and standard controls provide the base Liquid Glass/material hierarchy in light, dark, and Follow System modes. Do not force a color scheme, add an opaque navigation background, custom top operation strip, gradients, or repeated glass cards.
- `MicaGlassSelectionSurface` is the single custom glass primitive. It is for a small number of interactive selector blocks only; it uses `GlassEffectContainer`, `ConcentricRectangle`, Reduce Transparency fallback, and Reduce Motion-aware selection feedback.
- Tables, lists, logs, long text, inspector data, and policy members remain high-readability content layers. They do not receive individual glass cards.
- Policy selectors are fixed staggered content cards: after search and stable GLOBAL-last partition, visible indices `0,2,4...` stay in the leading column and `1,3,5...` stay in the trailing column. Expanding a group never rebalances columns. Narrow windows use the same flat semantic order. Multiple groups may remain expanded, each with independent filter, pagination, and bounded member scrolling.
- The bottom session status bar is always present at a stable font-scaled height. It shows controller identity, unified session state (connecting/live/paused/partial/failed), and last success when width permits; while paused, the time is the fixed pause instant rather than a moving network-success time. Transient operations replace only the center summary.
- Data-surface empty states use native `ContentUnavailableView`. The title names the state; the description explains the cause or next step. Never render the same localization key or sentence in both positions, and distinguish an unloaded/empty source from a filter with no matches. Keep top command areas in place, then center the empty state horizontally and vertically in the remaining content region.
- The Overview destination is the one dashboard that groups content into flat `dashboardCard` blocks (system `.regularMaterial` + soft separator border): a KPI tile row, the throughput chart, the three insight modules, inventory, and endpoint health. These cards are material, not glass — never `.glassEffect`/`MicaGlassSelectionSurface` — and never nest. Card titles use semantic-color SF Symbols; metric values share one numeric scale.
- Rose Pine Dawn/Main remains the semantic tint and opaque-fallback palette: purple for selection/focus, blue/green for healthy state, cyan for information/live state, yellow for warnings, and red for failures/danger. Window and content bases use system semantic colors/materials.

## Data And Preference Invariants

- Policy group order comes from controller `proxyOrder`; UI filtering changes visibility only and never calls `sorted`. Node options preserve their controller order. The GLOBAL group is the one presentation-layer exception: a user preference (`GlobalGroupVisibility`, "follow mode" default / "always show") decides whether GLOBAL is shown, and when shown it is placed last via stable partition (`arrangedGroups` keeps peer groups in order and appends GLOBAL) - never through `sorted` and never by touching the decode layer. Every peer group keeps its exact `proxyOrder`.
- An expanded policy group may expose an inline node filter scoped to that group. Filtering is case-insensitive, preserves duplicates and controller order, and runs against the complete `group.options` collection before `PolicyGroupInteractionStore` applies that group's local member window. Filter changes never mutate the selected policy group or selected node; clearing the filter restores the existing ordered pagination state.
- Every eligible node row exposes its own inline latency action without replacing node selection. Mihomo uses node/provider-scoped delay endpoints, Stash uses the bounded member fallback, and sing-box issues StartedService URLTest; the accepted sing-box request updates visible delay only when the group stream reports the result.
- Connections, logs, rules, and sources preserve their incoming presentation order. Search and category filters change visibility only. Connections, rules, and sources tables additionally support user-initiated column sorting through the native `sortOrder` binding: a declared default column order is seeded, the user may change it, and sorting always applies to a presentation-layer projection (`ordered(using:)` in the presentation types) — the source collections are never mutated and view files contain no direct `.sorted` call. The rebuilt workbench has no legacy local sort/group/page state (`ConnectionSessionSort`-style types stay deleted).
- Charts bind real controller data only. The time axis is reserved for the bounded received-sample `TrafficTimeline`; snapshot aggregates (latency grades, rule-type distribution, top connections) render as category charts with localized empty states and accessible numeric fallbacks, and never fabricate a time axis.
- Selecting a controller immediately creates one generation-scoped live session. Mihomo traffic/log/memory/connection WebSockets or Surge near-live polling run alongside REST lanes: fast 2s (connections/active requests), medium 5s (policy groups/current selection), and slow 30s (rules/providers/config/version). sing-box uses one structured StartedService task tree for status, groups, mode, connections, logs, and Tailscale. Manual refresh uses the same per-lane single-flight/coalescing path. There is no user-visible snapshot/sync mode or 10-second full polling loop, and localized copy must not imply Start/Stop Live controls.
- Every async result carries controller ID and generation. Select, active-controller save, active delete fallback, last-main-window close, sleep, and wake invalidate or create generations through the same lifecycle. App deactivation and minimization do not stop a session. The selected controller ID persists and is restored only after profiles and secrets load.
- Pause freezes all visible business data while network tasks continue. REST keeps the newest pending projection; traffic uses the session-owned five-minute/about-300-sample timeline; logs use a 2000-entry/8 MiB UTF-8 budget; closed connections use a 1000-entry/16 MiB estimate budget. Resume atomically publishes pending data and coalesces one immediate refresh. Pause is generation-scoped and never persisted. Test remains enabled; refresh, rules/source reload, and provider-update entry points all consume the shared paused-session capability and are disabled.
- Endpoint failure after a successful value never clears that value. Policy, connection, rule, and source surfaces keep their last rows and show an explicit stale marker; an error empty state is reserved for endpoints that have never produced data in the current generation.
- A confirmed remote write followed by refresh failure is partial success: retain the optimistic/confirmed result and explain the refresh failure. Roll back only when the write itself failed.
- Active UI shows complete controller business data. Endpoints, URLs, IDs, payloads, names, chains, and log messages wrap or remain selectable; never middle-truncate, mask, hash, or replace them.
- Exports exclude credentials, authorization values, subscription URLs, and raw response/stream bodies.
- Controller secrets persist through the `SecretStore` protocol, defaulting to `FileSecretStore` — a plaintext `secrets.json` keyed by profile UUID, in the same Application Support directory as `routers.json`. Secrets live in their own file, never inside `RouterProfile` (which only carries a `secretReference`), so the exports-exclude-credentials invariant holds without per-path scrubbing. `KeychainSecretStore` is retained but no longer the default. Injecting secrets into `RouterProfile`/`routers.json` is prohibited.
- Language, appearance, and all four font-scale choices are injected at the scene/root boundary and immediately repaint every area.
- Controller save and delete are awaitable transactions. Storage failure leaves profiles, credentials, selection, and the current generation unchanged. Editing the active controller replaces only that session after commit; editing or adding a non-active controller never steals it. Deleting the active controller selects the next item at the old index, otherwise the previous item; deleting a non-active controller has no session side effect.
- Controller editing stays in the detail region. Save closes only after commit; failure remains inline with the draft intact. Dirty cancel, destination changes, Add, and Edit Another use an inline discard gate; ordinary editor navigation never uses a sheet or popover. Saving disables those replacement paths. Closing a dirty main window is the destructive exception: `MainWindowCloseGuard` uses a native AppKit confirmation sheet and forwards the existing window delegate; it does not implement content UI.
- System configuration, actions, diagnostics, and settings use native forms. Controller editing stays in the main-window detail region; an empty target is explicitly unconfigured, secrets remain secure fields, and IPv6 display endpoints are bracketed.
- The Logs level picker remains available as a local filter whenever the backend supplies logs; changing the controller's upstream level requires the separate `logLevelChange` capability. sing-box Tailscale status and operations live in the Configuration destination and do not add a sidebar destination.
- Icon-only commands keep their glyph visually compact but expose a localized label/help string and at least a 44-point hit region.

## Validation

- `scripts/verify-real-controller-source.mjs` checks this durable contract and current source only; it must never read a Trellis task path or assert task status.
- Build, tests, and source verification stay network-free and do not load controller profiles or start a local core. Runtime smoke is optional and is skipped whenever the user requests no smoke testing.
- Visual checks cover normal/reduced transparency, reduced motion, VoiceOver, keyboard navigation, long business text, English/Chinese, light/dark/system appearance, and all font scales.
