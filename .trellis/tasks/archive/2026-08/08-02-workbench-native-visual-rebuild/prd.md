# Workbench 全页面原生视觉重构

## Goal

从当前真实源码和功能出发，重新设计 Mica 的完整 Workbench，使十项导航目的地形成统一、清晰、原生的 macOS 专业工具体验。重构必须解决当前页面层级混乱、容器滥用、颜色割裂、空状态与加载状态不统一、控件难点击、长列表滚动卡顿，以及局部修改导致布局反复变化的问题，同时保留控制器真实数据、功能和操作能力。

## Background

- Mica 是 Swift 6.2、SwiftUI、macOS 27 原生应用，控制已经运行的远程控制器；不管理本地核心和系统网络。
- 当前固定目的地为 Overview、Proxies、Connections、Logs、Rules、Sources、Controllers、Configuration、Actions、Diagnostics；应用偏好仅保留在原生 `Settings` scene。
- 用户已明确不接受继续兼容旧页面结构，允许完整重构；但功能、真实数据、控制器顺序、能力门控和同窗口工作流不得回退。
- 已确认页面不能继续共享一种“万能卡片”布局。当前 UI 契约已将页面分为监控台、数据浏览器、策略选择工作区、管理表单和诊断大纲。
- 本任务接续并保留工作区中尚未提交的设置、诊断、中文文案和源码验证修改，不回退这些修改。

## Requirements

### R1. 全页面范围

- 覆盖十项固定目的地、原生 Settings scene，以及共享侧栏、命令栏、底部状态栏、搜索/筛选、加载、空、失败、断线和保留旧数据状态。
- 侧栏保留十项直接入口，固定分为工作台和控制器管理两组；应用设置不在工作台重复。通过紧凑行高、完整行命中、弱化分组标题和低饱和选中态降低视觉重量。
- 共用视觉系统和交互原语，但按页面任务选择正确的信息架构，不强行统一成卡片、表单或表格。

### R2. 页面信息架构

- Overview 默认只显示真实上传、下载、活动连接三张主图表，以及完整连接拓扑和网络信息；内存作为连接图上下文，仪表条与运营摘要仅在用户个性化启用时出现。图表必须可悬停、选择、暂停和进入关联数据，不是装饰。
- Proxies 保持控制器报告顺序，可见 GLOBAL 始终置于末尾；策略组可多项内联展开、过滤节点、查看节点字段并点击切换，不使用弹窗。
- Connections、Logs、Rules、Sources 使用原生高密度数据浏览模式：稳定命令区、单一原生 Table、搜索/筛选/排序和同窗口检查器。
- Controllers、Configuration、Actions 使用受限宽度的管理布局；说明与控件关系稳定，宽屏不拉满，窄屏自然堆叠。原生 Settings scene 单独使用受限宽度 grouped Form。
- Diagnostics 使用无外框状态摘要和连续分层大纲；用户界面不展示 API 路径、机器键值串或原始报告正文。

### R3. 视觉与交互一致性

- 沿用当前 Midnight Instrument 语义色体系，不恢复 Rose Pine；允许调整各色使用面积、层级和透明度，但不建立第二套产品主题。
- 窗口、工具栏、侧栏、命令栏、内容区和底部状态栏在浅色/深色下使用一致的语义颜色。
- 内容层不使用自定义玻璃、渐变装饰、卡片套卡片或重复浮动面板；Liquid Glass 仅用于系统导航和控制层。
- 所有行级按钮和 disclosure 使用完整行点击范围；一级和二级展开使用一致动画并遵守 Reduce Motion。
- 使用 SF Symbols 和现有 Workbench 图标原语；图标、标题、状态和动作建立稳定层级。
- 字号设置只改变文字可见大小，不擅自切换页面信息架构；布局仅由实际可用宽度决定。
- 应用偏好只在系统 `Settings` scene 中显示，不在主窗口侧栏重复。当前设置数量不足以支撑第二层设置侧栏，因此保持单页 grouped Form；窗口 chrome 使用系统能力，内容区不添加自定义玻璃或 AppKit 平行实现。
- 标准菜单、Mica 自定义菜单和快捷键遵循同一有效菜单语言；不得出现 File/Edit/View 为英文而单独一个自定义菜单为中文的混合状态。

### R4. 状态、数据与功能完整性

- 不制造图表样本、策略节点、规则、连接、日志、来源或控制器能力；只呈现真实控制器数据。
- 断线或用户停止连接后，不把保留数据伪装为实时数据；状态必须明确为断线、暂停或过期。
- 保留控制器报告顺序和可选字段，不自动故障转移，不抢占现有会话。
- 不支持的功能和诊断项隐藏或显示明确不可用状态，不提供无效操作。
- 英文和简体中文覆盖所有可见文字、菜单、帮助、工具提示和无障碍标签。
- 格式化字符串必须通过带参数的本地化边界解析；任何 `%@`、`%d` 或位置参数不得原样显示在界面。

### R5. 性能

- 高频流量、连接、日志和内存更新只重绘对应子树；隐藏目的地不做昂贵投影。
- 大数据页面保持单一虚拟化 Table；滚动期间不在行 body 内重复格式化、排序、分组或创建昂贵材质。
- Overview 图表、拓扑和网络字段按可见性构建；Diagnostics 展开后仍保持顺畅滚动。
- 不为视觉重构引入第三方包。只有本地评估证明能带来必要且显著收益时，才能另行记录并批准。

### R6. 开发边界

- 只修改 Mica Workbench、必要的本地化、测试、验证脚本和项目文档/规范；不触碰系统网络或真实控制器。
- 临时文件只写入 `tmp/codex/`，结束时删除无用产物。
- 同一阶段集中完成修改后再验证，不在每个小补丁后运行完整构建或测试。
- Agent 不自动启动 Mica、不采集运行时截图；最终视觉截图和主观验收由用户执行。自动验证仅覆盖源码契约、本地化、构建、测试和静态检查，且不得连接真实控制器。

## Acceptance Criteria

- [ ] AC1：十项目的地、原生 Settings scene 与共享 chrome 均符合各自页面类型，浅色和深色下不出现割裂色带、系统白块、卡片嵌套或横向溢出。
- [ ] AC2：Overview 默认三张主图表使用真实样本并具备完整交互；拓扑显示完整链路且无嵌套横向滚动。
- [ ] AC3：Proxies 顺序稳定，支持多展开、节点过滤、完整字段和节点切换；交互不使用弹窗。
- [ ] AC4：Connections、Logs、Rules、Sources 各自只有一个原生 Table，搜索、筛选、排序、检查器和空/失败状态均可用。
- [ ] AC5：Controllers、Configuration、Actions 与原生 Settings scene 的字段说明可读、控件位置稳定、整行命中合理，并在窗口和字号变化时不发生错误重排。
- [ ] AC6：Diagnostics 摘要、大纲、两级展开、支持项过滤和安全报告复制均可用；不显示技术键值串、API 路径或原始正文。
- [ ] AC7：停止、断线、加载、空、无匹配、首次失败、保留旧数据七类状态在相关页面有明确且一致的视觉和文字。
- [ ] AC8：语言、外观和四档字号立即更新主窗口、Settings 窗口、菜单、帮助和无障碍文字。
- [ ] AC8a：菜单栏语言保持一致，所有可见本地化字符串均已完成格式化，不出现原始占位符。
- [ ] AC9：滚动和实时更新不引入明显卡顿；现有性能计数、投影缓存、稳定标识和发布预算测试保持通过。
- [ ] AC10：相关源代码契约、字符串目录检查、Swift build/test 和 `git diff --check` 通过；Agent 不启动应用、不运行真实控制器操作或 runtime smoke，最终视觉截图由用户验收。

## Out Of Scope

- AppKit 全面迁移、改变控制器协议或新增 OpenSurge 能力。
- 下载、捆绑、启动或管理本地核心。
- 修改系统代理、网络、防火墙、OpenWrt、LuCI、SSH 或 `ubus`。
- 发布、DMG、签名、Sparkle 或 App Store 工作。
