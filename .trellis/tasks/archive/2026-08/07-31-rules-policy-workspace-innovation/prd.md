# 规则与策略组创新工作区

## Goal

把规则页与策略组页重构为原生 macOS“决策路径工作区”，让用户快速看清
`规则 → 目标策略` 和 `策略组 → 当前节点 → 候选节点`。创新用于提高理解、
选择和比较效率，不增加卡片墙、装饰动画或滚动负担。

## Background

- 规则页已有单棵原生 `Table`、宽度模式、稳定选择/排序/滚动恢复、页面投影
  缓存和完整 inspector。
- 策略组页已有来源顺序目录、多组打开、每组独立过滤/检查选择、活动组单棵
  原生 `List`、节点详情和目录/节点投影缓存。
- 控制器组和节点必须保持上报顺序；过滤不得重排；可见 `GLOBAL` 位于普通组
  之后。关闭活动组时，现有状态投影会优先激活下一项，否则激活上一项。
- SMART 使用等级来自控制器 `/group/weights`；客户端不得推断或据此排序。
- 当前策略页在 640 点宽仍强制约 `240 + 399` 的左右分栏，窄窗口会挤压目录、
  节点列表和详情。

## Requirements

### R1. Shared Decision-Path Language

- 两页共享克制的路径语法：SF Symbol、文字、细连接线和语义色；不使用节点
  气泡、渐变、嵌套卡片、自定义内容玻璃或持续动画。
- 上下文焦点条位于扫描区域上方并限制高度。规则未选中时移除焦点条；策略页
  存在活动组时显示焦点条。
- 普通命令使用图标或无底色文本，不形成连续方块按钮。系统玻璃只用于窗口、
  侧栏和工具栏。
- 完整主机、规则 payload、策略名、节点名和控制器字段在活动界面全量可见。

### R2. Rules Workspace

- 保留来源顺序、搜索、用户排序、选择与滚动恢复、单棵 `Table`、规则 mutation
  和完整 inspector。
- 扫描行优先表达规则定义与目标策略；状态、命中数和活跃连接作为次级信息。
- 选中规则后显示真实的
  `规则类型 → 匹配内容 → 目标策略`，并显示启用状态、命中/未命中、活跃连接
  及可用操作；不伪造缺失值。
- 目标策略与当前控制器可见策略组名称精确匹配时可点击。点击后按来源顺序打开
  并激活目标组，再导航到策略组页，同时保留目标组已有过滤和节点检查选择。
- `DIRECT`、`REJECT`、普通节点名及无法精确匹配的目标只显示，不推断、不跳转。
- 未选中规则时不保留空焦点条或空 inspector。

### R3. Policy Workspace

- 保留来源顺序目录、多组打开、每组独立过滤/检查选择和仅渲染活动组节点列表
  的性能边界。
- 普通标签页替换为“已打开路径带”。每项显示
  `策略组 → 当前节点`，按来源顺序排列；当前项只使用底部细线强调。关闭命令
  在悬停、键盘焦点或当前状态时出现。
- 路径带不横向滚动。宽度不足时把尾部项目按原顺序放入溢出菜单，并在菜单中
  标记当前项。
- 策略组目录行分成两个明确命中区域：
  - 组名区域只打开或激活；再次点击当前组不会关闭。
  - 尾部 disclosure 显式打开/关闭；路径带关闭命令也可关闭。
- 关闭活动组后优先激活来源顺序中的下一项，没有下一项时激活上一项。
- 活动组焦点条显示完整策略路径、当前节点、延迟、固定选择和真实控制器状态。
- 节点行区分控制器当前节点、工作区检查节点、可切换状态、健康状态、延迟和
  控制器上报的 SMART 使用等级。
- 有真实延迟的节点显示组内比较轨道，并始终显示精确毫秒值。轨道只在活动组
  内归一化；无延迟不绘制，也不按 `0 ms` 处理；任何比较不得改变来源顺序。
- 点击节点在控制器允许时立即切换并打开详情。详情由工作区检查选择驱动且可以
  关闭；关闭详情不改变控制器当前节点。未检查节点时不预留空 inspector。
- 组测试、节点测试、节点切换和解除固定选择都在主窗口内完成。

### R4. Adaptive Layout And Accessibility

- 宽窗口使用“左侧策略组目录 + 右侧节点工作区”，总体内容宽度继续受合理上限
  约束。
- 空间不足时改为同页上下布局：目录成为默认收起的顶部区域，收起时显示当前组
  摘要，展开后原地选择；节点工作区占据完整宽度。
- 紧凑布局不使用 sheet、popover、独立窗口或横向页面滚动。宽窗口详情位于
  右侧，窄窗口详情位于同页底部。
- 常规、紧凑、最窄窗口和超大字体下，路径、名称和关键命令不得重叠或变得
  不可达。组名区、disclosure、路径关闭和节点操作均有独立辅助功能语义。

### R5. Performance And Data Integrity

- 不新增 mock 数据，不修改控制器 API、规则语义、策略算法或 SMART 权重算法。
- 只为当前规则或活动策略组生成焦点路径；不同时构建多个大型节点列表。
- 延迟、连接数和操作状态的高频更新不得重建规则静态索引、策略组目录、搜索
  索引或非活动组节点。
- 继续使用 SwiftUI、`Table`、`List` 和系统 SF Symbols。本任务不引入第三方
  依赖，也不引入 AppKit 列表桥接。

## Out Of Scope

- 修改连接、日志、来源、配置或首页。
- 引入 OpenSurge、Zashboard、SparkXie 的运行时代码。
- 自由缩放图编辑器、拖拽重排、客户端学习策略或推断链路。
- 为旧策略页标签、头部或固定 inspector 保留兼容包装。

## Acceptance Criteria

- [x] AC1: 选中规则能看到完整真实的
  `类型 → payload → 目标策略`，未选中时无空焦点区域。
- [x] AC2: 精确匹配的规则目标能打开并激活对应策略组；不可匹配目标没有伪链接。
- [x] AC3: 规则页继续保留单棵虚拟化 `Table`、搜索、排序、来源顺序、选择恢复、
  mutation 和完整详情。
- [x] AC4: 活动策略组能看到
  `策略组 → 当前节点 → 候选节点`，节点点击按能力立即切换。
- [x] AC5: 路径带保持来源顺序且无横向滚动；尾部溢出不丢失打开组或当前状态。
- [x] AC6: 组名点击不意外关闭；disclosure 和路径带关闭均有效；关闭后的活动组
  遵循“下一项优先，否则上一项”。
- [x] AC7: 节点延迟轨道使用真实组内数据、保留精确值、不处理缺失值且不重排。
- [x] AC8: SMART 等级只显示控制器上报结果；无数据时不显示推断标签。
- [x] AC9: 节点详情按检查选择出现/关闭；关闭详情不改变控制器当前选择且不留下
  固定空栏。
- [x] AC10: 紧凑策略组页使用同页上下布局，宽窗口使用双栏；所有支持宽度和超大
  字体下无关键重叠、横向页面滚动或不可达命令。
- [x] AC11: 规则与策略页不出现卡片墙、嵌套玻璃、连续方块按钮或持续动画。
- [x] AC12: 现有投影、来源顺序、mutation、持久化和性能测试继续通过，并增加
  跳转解析、路径带、布局、延迟轨道和详情生命周期的防回归测试。
