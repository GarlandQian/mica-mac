# 本地化占位符与全局表单布局修复

## Goal

彻底消除 Mica 可见界面和诊断文本中的原始格式占位符（如 `%@`、
`%lld`），并将所有管理页面的字段标签与控件统一锚定到内容左侧。修复必须
覆盖当前字符串目录和管理工作台中的全部同类错误，而不是只处理截图中的
几个字段或设置页。

## Confirmed Evidence

- `Localizable.xcstrings` 当前有 31 个条目：键不含格式参数，但英文或简体中文
  值包含 `%@`、`%d` 等参数。
- `diagnostics.active_controller`、`diagnostics.controller_health`、
  `diagnostics.version` 和 `diagnostics.mode` 同时被静态表单标签与参数化诊断
  文本使用，静态查找会直接显示 `%@`。
- 参数化诊断调用生成带 `%@` / `%lld` 的语义键，但目录中只有不带参数的键，
  因而可能回退为内部键或错误文本。
- `dashboard.switch_node` 作为普通按钮和辅助功能标签使用，但其目录值要求两个
  参数。
- 设置页四个偏好项使用原生 `LabeledContent`；宽窗口下系统值列位于表单中部，
  与用户要求的左对齐不符。
- 配置页字段也使用默认 `LabeledContent`，且模式、日志级别和只读多行值显式
  右对齐；Tailscale 内嵌详情另有一处默认值列。
- 控制器编辑、控制器详情和诊断页大多已使用 `WorkbenchFormRow`，但缺少统一
  契约来约束设置、配置和内嵌详情。

## Requirements

### R1. String Catalog Contract

- 参数化条目的目录键必须声明与英文、简体中文值一致的格式参数签名。
- 静态标签、按钮标题和辅助功能名称不得复用需要参数的整句。
- 同一概念同时需要标签和参数化消息时，保留独立的静态键与参数化键。
- 不得通过渲染时删除 `%@`、隐藏文本或替换为占位内容来掩盖目录错误。
- 对未被引用的异常目录项，只有在确认没有动态消费者和验证器依赖后才能删除；
  否则迁移为语义明确的静态或参数化条目。

### R2. Complete Placeholder Remediation

- 修复当前审计发现的全部 31 个异常条目及其调用点。
- 对整个字符串目录执行结构化审计，不能只匹配截图中的诊断键。
- 普通百分号和 `%%` 转义不得被误判为参数。
- 用户可见文本不得出现未解析的 C 格式标记或内部本地化键。

### R3. Runtime Localization Behavior

- `MicaStrings.localizedKey` 只解析静态键；参数化文本继续通过
  `MicaStrings.localized` 和 `String.LocalizationValue` 语义键解析。
- 英文、简体中文和“跟随系统”必须使用相同的键契约。
- 语言切换后的短期状态重定位继续支持参数化文本。
- 除非测试证明现有分解逻辑有缺陷，否则不扩大
  `String.LocalizationValue` 反射实现的修改范围。

### R4. Left-Aligned Management Forms

- 设置、控制器编辑、控制器详情、配置、操作、诊断及管理内嵌详情中的字段行
  必须使用统一的左对齐布局契约。
- 字段控件和值必须位于稳定标签列之后，并与表单内容左侧形成清晰的两列关系。
- 宽窗口不能把控件推到卡片中间或右侧；控件后方剩余空间由弹性空白吸收。
- 窄窗口或超大字体无法容纳两列时，标签与控件纵向堆叠且都左对齐。
- Workbench 设置页和原生 Settings 窗口继续共享同一组偏好绑定和布局行为。
- 配置页的模式、日志级别、布尔开关和只读值不得继续使用默认居中/右对齐值列。
- Tailscale 等内嵌 disclosure 的“字段名 + 值”必须明确左对齐，不依赖默认
  `LabeledContent` 值列。
- 保留原生 `Picker`、分段控件、Toggle、TextField、帮助文本、键盘操作和
  辅助功能语义。
- 工具栏命令、计数、状态摘要和头部元数据不属于字段行；其语义需要靠右时
  保持原布局。

### R5. Scope And Compatibility

- 保持原生 SwiftUI、Swift 6.2 和 macOS 27，不为本修复新增第三方依赖。
- 不改变控制器数据、认证、连接、诊断导出边界或偏好持久化行为。
- 不接触真实控制器、本机 9090、核心进程或系统网络设置。
- 不运行旧 runtime smoke；构建和测试集中在实现结束后执行。

### R6. Regression Protection

- 源码验证器必须拒绝“键无参数、翻译值有参数”和各语言参数签名不一致。
- 单元测试必须分别覆盖静态标签、字符串参数、整数参数和语言切换重定位。
- 管理字段布局必须有可维护的源码/结构测试，防止设置、配置或内嵌详情重新
  退回自动居中/右对齐的 `LabeledContent` 默认样式。

### R7. Approved Follow-Up: Proxy Node Fields

- 策略组中选中的节点必须在现有同窗口检查器内显示结构化字段详情。
- 概况、传输能力、测试与延迟使用语义字段；控制器原始节点对象的每个顶层
  字段按稳定键顺序逐行完整显示，不再合并成一段 JSON。
- `true` 与 `false` 传输状态都必须保留；控制器未上报的字段不得伪造。
- 原始字段排序与 JSON 值格式化只针对当前选中节点执行，不能把编码成本扩散
  到整个节点目录或节点列表滚动热路径。
- 继续使用现有主从布局、滚动检查器和原生 SwiftUI，不新增弹窗、横向滚动轴
  或第三方依赖。

### R8. Approved Follow-Up: Management Settings Visual Hierarchy

- 设置、配置、操作和诊断页必须使用同一条左侧有限宽度内容轴，不得继续把
  大表单居中或拉伸到整个工作区。
- Workbench 设置、操作、控制器详情和诊断使用无圆角的扁平内容带、上下
  分隔线和不透明内容背景；配置和原生 Settings 窗口保留 grouped `Form`。
- 设置字段必须显示现有帮助文案，标签为主要文字，控件紧接稳定标签列；
  窄宽度继续纵向堆叠。
- 不新增 AppKit 内容控件、第三方依赖、自定义内容玻璃、嵌套卡片或业务行为
  变化。

### R9. Approved Follow-Up: Preference Control Chrome

- 语言、外观、字体大小和 GLOBAL 显示选项使用统一、紧凑的原生菜单。
- 每行只显示当前值及一个展开指示，不再使用连续分段方块。
- 菜单保留语义 SF Symbol、当前项标记、键盘、help 和辅助功能值。
- 不为偏好控件增加自定义背景、描边、玻璃或第三方组件。

### R10. Approved Follow-Up: Rules Scan Hierarchy

- 规则表格将 payload、类型和索引合并为一个主要定义层级，避免重复列。
- 路由、活跃连接、命中数和状态保持可扫描，完整字段继续在同窗口检查器显示。
- 状态使用圆点与文字，不使用背景徽章；启停操作并入状态或复合摘要，不再
  单独占据一个按钮方格列。
- full、compact 和 stacked 继续由同一个原生 `Table` 构造，不能改变规则
  原始顺序、搜索、用户排序、持久化选择或控制器 mutation 边界。

## Out Of Scope

- 全面改写中英文文案或重新设计 Settings 信息架构。
- 修改诊断报告包含的数据、控制器能力或导出隐私边界。
- 重构 Overview、连接、日志、规则和来源等非表单数据页面，以及策略组目录、
  节点列表和切换流程。
- 改变工具栏、状态摘要、表格列或其他非字段行的语义对齐。
- 处理 Xcode DerivedData 磁盘 I/O 故障。

## Acceptance Criteria

- [x] AC1: 全目录结构化审计报告 0 个“静态键包含参数化翻译值”的条目。
- [x] AC2: 每个参数化条目的键、英文值和简体中文值具有一致的参数数量、顺序和
  类型。
- [x] AC3: 诊断控制器字段、策略节点切换控件及其他静态调用不再显示 `%@`、
  `%lld`、`%d` 或内部本地化键。
- [x] AC4: 诊断报告中的字符串值和整数计数在英文、简体中文下正确插值，语言
  重定位仍然正确。
- [x] AC5: 设置、控制器、配置、操作、诊断和管理内嵌详情的字段控件/值在常规
  宽度下从统一左侧控件列开始，不再位于卡片中心或右侧。
- [x] AC6: 窄宽度和超大字体下，所有受影响字段行自然堆叠且无截断、重叠或
  横向溢出。
- [x] AC7: Workbench 与原生 Settings 窗口继续修改同一
  `AppPreferencesStore` 状态，外观、语言、字体和 GLOBAL 显示设置行为不变。
- [x] AC8: Picker、Toggle、TextField、只读可选择文本、help 和辅助功能行为
  在统一布局后保持可用。
- [x] AC9: `swift build`、`swift test`、字符串目录 JSON 验证、源码契约验证
  和 `git diff --check` 全部通过。
- [x] AC10: 没有访问真实控制器、9090、核心进程或系统网络，也没有运行旧
  runtime smoke。
- [x] AC11: 选中节点检查器按概况、传输能力、测试与延迟、控制器字段分组，
  且所有控制器原始顶层字段均为独立、可选择的键值行。
- [x] AC12: 传输状态同时保留启用与停用值；嵌套对象、数组、空字符串、
  布尔值、数字和 `null` 使用确定性文本格式。
- [x] AC13: 原始字段投影只在当前选中节点详情边界生成，并由测试和源码验证器
  防止退回整段 JSON 或全目录预计算。
- [x] AC14: Workbench 管理内容列锚定左侧并限制宽度，配置和设置不再由两侧
  Spacer 居中。
- [x] AC15: 设置、操作、控制器详情和诊断共享扁平内容带；原生 Settings 与
  Workbench 仍共享偏好绑定和字段内容。
- [x] AC16: 设置帮助文案可见，字段标签列缩短为 176 点，常规与紧凑宽度
  均保持左对齐、无横向溢出。
- [ ] AC17: 四个偏好选项统一使用无底色菜单，外观和字体大小不再显示分段
  方块，同时保持即时绑定、键盘和辅助功能行为。
- [ ] AC18: 规则页不再显示重复类型列、方块状态徽章或独立操作按钮列；
  三种宽度模式保持完整可扫描字段、单表构造和同窗口详情。

## Notes

- 当前 31 个异常项包括 5 个 `dashboard.*` 和 26 个 `diagnostics.*` 条目。
- 用户截图是验收样例，不是修复范围上限。
