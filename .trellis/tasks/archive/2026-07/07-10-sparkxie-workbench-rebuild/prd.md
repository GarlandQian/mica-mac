# Mica SparkXie 对齐控制器工作台全量重构

## Goal

完全重构 Mica 的原生 macOS 控制器工作台。旧的 tab 布局、卡片结构、图表/deck 抽象、Command 菜单分组、显示策略和兼容包装都不作为约束；新实现必须从真实控制器数据和 SparkXie 的数据语义重新建立信息架构。

用户打开任何 tab 后，都应能直接看懂当前控制器返回的对象、字段、状态、关系和可执行操作。所有界面、数据层和交互决策以 SparkXie 项目的真实展示为主要参考，而不是继续修补当前看不懂的抽象展示。

## Background

- 参考项目：`https://github.com/UruhaLushia/sparxie`。
- SparkXie 参考 checkout 位于 `tmp/codex/sparxie-ui-reference`；本任务 PRD、设计和实施计划是当前唯一的项目目标文档。
- 本次是从头重构现有工作台，不要求兼容之前的 tab 布局、旧的 command palette 分组、旧的抽象 chart/deck 层或旧的显示策略。
- 当前产品是远程控制器 UI，不负责下载、打包、启动或运行真实 core。
- 控制器业务数据在活动界面全量可见：endpoint/host、请求 URL、连接 ID、来源名称、节点/策略名称、规则 payload、路由链、日志消息都不能被隐藏、脱敏或替换成模糊摘要。

## Requirements

### R1. 以真实数据模型重建 tab

以下页面必须全部重构并分别对应 SparkXie/控制器真实可获得的数据对象：

- 概览：上传/下载速度、连接数量、内存/运行时、核心版本/模式、总量和端点状态。
- 代理组/策略组：组类型、当前节点、成员数量、节点名称/类型、延迟、固定/选中状态和控制器返回的隐藏状态。
- 连接：连接 ID、主机、进程/来源、网络类型、当前代理、上传/下载总量与速度、开始时间，以及进程/规则/路由链聚合。
- 分流规则：规则类型、payload、proxy/outbound、extra 参数和适配器真实提供的命中/未命中/大小等字段。
- 日志：级别、时间戳和原始控制器消息，支持筛选、暂停、继续、清空和跟随底部。
- 外部资源/来源：代理来源、规则来源、名称、vehicle、behavior/format、节点/规则数量、更新时间和更新能力。
- 核心配置：模式、日志级别、TUN、LAN、IPv6、TCP 并发、端口等真实可写字段。
- 核心操作：重载配置、GeoData 更新、重启、升级、DNS/FakeIP 缓存清理等真实能力，危险操作必须确认。
- Tailscale：仅在后端支持时显示 sing-box Tailscale 端点、认证 URL、后端状态、peer 和 exit node。
- 诊断：端点检查、能力矩阵、数据可用性、运行时操作可用性、错误和报告导出。
- 设置：语言、外观、字体大小、控制器配置和应用偏好，不重复承载连接/规则等业务表格。

字段缺失时显示明确的 unavailable/未提供状态，不得填充假计数、假图表、假延迟、假命中率、假连接或示例数据。

### R2. 主页提供可解释的控制器概览

主页可以使用图表，但图表只能由真实快照或明确的时间序列数据驱动，并且要能追溯到对应的连接、来源、规则、日志或流量数据。没有真实序列时显示对象列表、状态和更新时间，不绘制抽象装饰图表。

### R3. 策略组使用固定顺序的展开式工作区

- 策略组按控制器返回顺序或用户已有顺序稳定显示，刷新、筛选、选择节点都不能自行重排策略组。
- 每个策略组是同一主窗口内的可展开/收缩区域，展开后显示当前策略、候选策略或节点、类型、健康状态、延迟信息和可用操作。
- 点击策略组后在当前窗口完成策略/节点选择，不使用普通 popover、sheet、modal 或 context menu。
- 液态玻璃只用于导航、工具栏和操作层；策略组、表格、列表等数据内容不能层层叠加玻璃效果。
- 策略组显示为一块一块清晰的可展开工作区，展开/收缩只影响内容可见性，不改变组的原始顺序、ID 或选择状态。
- 节点搜索、延迟测试、加载更多、固定选择取消和节点切换都在同一窗口的展开区域完成。

### R4. Command 入口清晰且可执行

Command 菜单必须按真实操作分组，显示命令名称、作用范围、快捷键和当前可用状态；不得把调试信息、抽象状态或无法执行的动作伪装成命令。普通操作在主窗口完成，只有破坏性或高风险动作才允许确认对话框。

### R5. 数据表和检查器优先呈现业务主字段

列表、表格、检查器和搜索结果要以 SparkXie 的主字段顺序展示：业务对象名称或 payload 优先，类型、目标/来源、状态、统计和辅助字段随后。每个 tab 的搜索、筛选、排序和分页必须作用于真实字段，并保持顺序稳定。

不允许通过多层卡片、抽象指标胶囊、模糊摘要或隐藏字段来替代真实数据。所有表格的主列必须先显示用户要判断的业务对象，再显示技术辅助字段。

### R6. 视觉和交互质量

- 所有 UI 设计都使用 `design-taste-frontend` 作为反模板化审查层，并结合 macOS/SwiftUI/HIG 规范。
- 使用固定的 Rose Pine Dawn-Main 色板：背景 light `#FAF4ED` / dark `#191724`，分组背景 light `#FFFAF3` / dark `#1F1D2E`，次级分组背景 light `#F2E9E1` / dark `#26233A`，三级分组背景 light `#DFDAD9` / dark `#403D52`，accent light `#907AA9` / dark `#C4A7E7`；其余语义色遵循 `AGENTS.md` 的完整 token 表。保证内容层对比度，避免无意义渐变、重复卡片、奇怪图标和过度圆角。
- 采用系统 SF Symbols，按钮提供可访问名称，支持键盘导航、VoiceOver、动态字体和跟随系统外观。
- 中文/英文、浅色/深色、跟随系统、字体缩放必须对所有主 tab 和命令入口立即生效。

### R7. 安全与运行边界

- 不修改系统代理、环境变量、防火墙、OpenWrt/LuCI、SSH 或 ubus。
- 不启动、下载、打包或运行真实 core。
- 活动 UI 保持业务数据全量可见；只有复制/导出报告排除凭据、token、X-Key、订阅 URL、authorization header、Keychain 内容和原始响应/流体内容。

### R8. 语言、外观和字体设置必须真实生效

- 中文选择后，主窗口、所有 tab、设置、Command 入口、菜单、帮助文字、tooltip 和辅助功能标签必须同步切换为中文；英文同理。
- `跟随系统 / 浅色 / 深色` 必须立即影响窗口、导航、工具栏、数据内容和设置预览，不允许只修改偏好值而不改变界面。
- `标准 / 舒适 / 大 / 特大` 字体大小必须立即影响设置、概览、策略组、表格、Command、连接、规则、来源、日志和诊断，并保持列布局稳定。
- 所有界面文案必须使用本地化资源，禁止把英文界面字符串硬编码到中文界面。

### R9. 完全可见与临时文件规则

- 活动控制器工作区全量显示控制器报告的业务数据：endpoint/host、URL、连接 ID、来源名、节点名、策略名、规则 payload、路由链、日志文本和状态值。
- 不在活动 UI 中使用 `redacted`、`masked`、`safe summary` 等隐私时代替词。
- 代码、日志、截图、构建产物、DerivedData、运行时 home 和验证输出等临时文件统一放在仓库 `tmp/codex/`。
- 每次开发结束删除不再需要的临时文件；保留的 SparkXie 参考 checkout 只有在后续任务仍需要时才保留。

## Acceptance Criteria

- [x] 每个主 tab 都有与 SparkXie 数据对象对应的明确布局、字段和空状态；没有 mock data 或虚构指标。
- [x] 主页的每一张图表都能追溯到真实快照/时间序列；没有可追溯数据时不显示图表。
- [x] 策略组顺序在初始加载、刷新、搜索、选择策略和切换 tab 后保持稳定。
- [x] 策略组选择在主窗口内完成，展开/收缩和节点选择不依赖普通弹窗或 popover。
- [x] Command 入口只展示真实可执行命令，并能在主窗口中定位到对应操作或数据区域。
- [x] 规则、来源、连接、日志和流量表格的主字段顺序与 SparkXie 数据语义一致，搜索/筛选/分页不产生虚假结果。
- [x] 概览、代理组、连接、规则、日志、来源、核心配置、核心操作、Tailscale、诊断和设置均完成独立的真实数据、空状态和不可用状态验收。
- [x] 策略组使用展开收缩的块状工作区，组顺序在所有刷新、筛选、选择和切换操作后保持不变。
- [x] 活动 UI 不隐藏或脱敏控制器业务数据；复制/导出时仅排除凭据和原始响应体。
- [x] 中英文、外观跟随系统/浅色/深色、四档字体大小在主窗口、设置、命令入口和全部主 tab 中可见且立即生效。
- [x] 主菜单、Command 入口、tooltip 和辅助功能标签没有遗留英文或错误中文翻译。
- [x] 通过 Swift 构建、单元测试、源码规则校验和运行时 smoke 校验；临时验证产物只写入 `tmp/codex/`，任务结束清理不再需要的临时文件。

## Out Of Scope

- 不兼容旧 UI 结构，不为删除的抽象概念增加兼容包装。
- 不实现真实 core 的安装、下载、启动、运行或代理接管。
- 不在没有控制器数据支持时推断或补造策略、节点、连接、流量、延迟、命中率或历史序列。
- 不把普通工作流改造成弹窗式设置或多窗口流程。
- 不为了保留旧 UI 名称、旧数据模型或旧命令入口而增加兼容包装。
- 不制作脱离真实数据的首页装饰图表；只有真实快照或时间序列存在时才允许图表。

## Open Questions

- SparkXie 与 Mica 控制器适配器对个别字段的可用性可能不同；实现前需要按 tab 逐项确认真实 API 字段，并将缺失字段标为 unavailable，而不是扩大数据模型来填假值。这是实现核对项，不阻塞任务创建或进入规划。
