# 首页视觉与交互精修

## Goal

把 Overview 重构为可在数秒内读懂当前控制器状态的原生 macOS 27
个性化监控台。页面需要有明确主次、精确的数据表达和流畅的滚动交互，
同时保留真实数据、完整链路、既有操作能力和上一轮建立的性能边界。

## Background

- 当前实现集中在 `WorkbenchDashboard.swift`，由一个纵向 `ScrollView`
  和 `LazyVStack` 承载，内容宽度上限为 1,180 点。
- 当前首页已包含四个实时读数、流量与内存时间线、延迟/规则/连接摘要、
  完整连接拓扑和控制器网络信息，不需要新增控制器 API 或业务统计。
- 时间线已有真实接收时间、悬停、单击固定、样本步进和返回实时；拓扑已有
  完整路径、悬停/固定高亮和同窗口 Connections 跳转。这些交互必须保留。
- `07-30-vertical-scroll-jank` 已建立单一纵向滚动、时间线缓存、拓扑异步
  布局与分层渲染边界。本任务不能重新引入嵌套纵向滚动、全树高频失效或
  每次交互重算完整拓扑。
- 当前会话头、四张 KPI 卡、图表、三组长摘要、拓扑和字段网格连续等权
  堆叠，颜色与节奏竞争注意力；网络字段也缺少稳定语义分组。
- Mica 使用固定 graphite/cyan 视觉系统。业务内容保持不透明，Liquid Glass
  只由原生窗口、工具栏和交互控件提供。

## Requirements

### R1. First-Viewport Hierarchy

- 删除完整首页会话头。控制器名称留在侧栏，页面标题留在原生工具栏，
  完整会话状态和时间留在固定底栏，版本与模式归入网络信息。
- 取消四张独立 KPI 卡，改为一条低矮统一仪表带。上传、下载、活动连接和
  内存使用共同数字基线与细分隔线；仪表带只增加一个实时/过期状态点。
- 默认布局的唯一首屏主角是上传/下载主时间线。内容保持在现有 1,180 点
  上限内，并在常见窗口首屏露出下一节提示，不做全宽监控墙。
- 使用系统主/次前景色承载正文。cyan 只表示选择、焦点或实时状态，mint、
  amber、red 表示真实健康级别，violet 只区分第二条图表序列。

### R2. Telemetry Workspace

- 上传与下载共享一个完整主时间线和统一读数区。
- 内存趋势改为主图下方约 64-80 点高的次级轨道，不再作为右侧独立图表。
- 流量与内存共享时间窗口、游标、固定点、样本步进和返回实时控制。
- 只绘制真实接收样本；不补点、不制造时间轴、不使用会越过真实值的平滑。
- 轴线、网格、图例和选中状态保持低噪声，同时保留数值与辅助功能回退。

### R3. Operational Summaries

- 延迟异常、规则命中和活动连接收进一个复合“态势摘要”模块，不在拓扑
  之前形成十五行数据墙。
- 宽布局在模块内同时显示三类摘要，每类默认最多三项；窄布局使用原生分段
  控制一次显示一类。用户可分别调整类别顺序、显隐和 1、3 或 5 项数量。
- 三类数据保持各自语义和真实顺序规则，不合并排名；复合模块可见时至少
  保留一个可见类别。
- 每项继续支持进入对应完整页面；连接项继续选中对应完整连接。

### R4. Complete Route Topology

- 完整拓扑继续留在 Overview，展示每条活动连接和每个控制器报告的链路节点。
- 默认使用低对比中性连线，通过列标题、SF Symbol 和小型层级标记区分语义。
- 仅悬停或固定的完整目标路径使用 cyan；最终节点可使用真实健康状态色。
- 不使用持续动画。拓扑可保留横向检查，但不得拥有第二个纵向滚动轴。
- 现有异步规范化、布局缓存、渲染分带、命中索引、辅助功能和 Connections
  跳转边界必须复用或等价保留。

### R5. Complete Network Information

- 网络信息始终完整展开，不折叠、不分页、不隐藏控制器报告的有效值。
- 现有字段按“控制器身份”“运行与功能状态”“监听端口”组织为对齐定义列表。
- 用户可以调整三个字段组的顺序，但组内字段保持完整和稳定。
- 缺失字段使用既有未报告语义，不制造占位业务值。

### R6. Constrained Personalization

- 首页采用受约束模块网格，不使用任意坐标、像素尺寸、重叠或自由画布。
- 模块目录固定为：仪表带、遥测、态势摘要、完整拓扑、网络信息。每种模块
  最多一个实例；态势摘要内部管理延迟、规则和连接三个类别。
- 用户可以拖动排序、显示/隐藏，并选择模块支持的紧凑、标准或通栏尺寸；
  系统负责对齐、响应式换行和窄窗口单列降级。
- 所有模块都允许隐藏，但布局必须至少保留一个可见模块。隐藏模块不得继续
  触发昂贵投影，完整 destination 仍可直接访问。
- 仪表带支持四个指标的排序与单项显隐且至少保留一个；遥测保存默认时间
  窗口；态势摘要保存类别顺序、显隐和 1/3/5 项；网络信息保存字段组顺序。
  不支持公式、脚本、任意 API 字段、派生统计或模块多实例。
- 控制器不支持某模块所需能力时，保留该模块的位置与配置并显示可访问的
  不可用状态；不得静默删除、隐藏或重排。

### R7. Layout Defaults And Persistence

- 提供“实时态势”“链路分析”“轻量监控”三个内置布局预设。预设只定义模块
  顺序、显隐和合法尺寸，不包含业务数据，也不覆盖模块内容设置。
- 预设先在当前窗口草稿中预览，只有完成编辑后才提交。
- 保存一套全局默认模板和每个控制器的一套覆盖；新控制器使用全局默认。
- 提供“重置当前控制器”和“设为新控制器默认”。重置移除当前控制器覆盖，
  重新使用全局默认；设为默认只标记当前草稿，仍由完成操作一次提交。
- 首版只本机持久化，不提供多套命名监控台、导入、导出、分享或跨设备同步。
- 未知、重复、非法尺寸或损坏的持久化内容必须规范化；无法恢复时回退到
  有效默认布局，不能导致空白首页或崩溃。

### R8. Inline Transactional Editing

- 个性化只在 Overview 内完成。工具栏图标进入编辑模式；顶部内联编辑栏
  提供预设、重置、设为默认、取消和完成。
- 模块标题在编辑模式显示拖动手柄、合法尺寸与隐藏命令；页面底部显示可
  恢复隐藏模块的区域。
- 不为普通布局操作使用弹窗、sheet、popover、上下文菜单、独立设置页或
  右侧检查器。
- 编辑使用窗口本地事务草稿：修改立即预览，完成一次提交，取消恢复进入
  编辑前布局，并通过窗口 `UndoManager` 支持 Cmd-Z/Shift-Cmd-Z。
- 编辑期间停用模块业务交互，但允许实时数据继续更新。
- 多窗口共享提交后的布局。若另一个窗口正在编辑同一控制器，保留其草稿并
  显示基础布局已变化的内联冲突提示，不静默覆盖。
- 编辑会话属于当前窗口而不是 Overview 视图生命周期。脏草稿存在时，
  destination 切换、控制器切换和关窗必须先走同窗口放弃/继续编辑流程；
  清洁草稿可直接取消。仅脏关窗允许使用原生破坏性确认。
- destination 必须属于各自窗口，不能再由一个窗口导航另一个窗口。控制器
  会话仍是应用级唯一选择；若其他窗口切换或删除了草稿目标控制器，当前
  草稿进入暂停冲突态并保留，只有显式保存到仍存在的目标、设为全局默认或
  放弃后才能继续。
- 每个窗口独立注册当前 destination 的实时发布需求。应用按所有可见窗口的
  domain 并集发布；一个窗口打开 Logs、Connections 或其他页面不得停止另一
  窗口 Overview 所需的 traffic、connections 和 memory。

### R9. Native, Responsive And Accessible

- 使用 SwiftUI、Swift Charts、Canvas、SF Symbols 和系统控件；本任务不为
  视觉方便引入第三方 UI 或图表依赖。
- 内容区不使用自定义 `.glassEffect`、渐变背景、发光、嵌套卡片或大面积
  彩色面板；圆角不超过现有 8 点模块规范。
- 保持一个纵向滚动所有者。360、720 和 1,180 点内容宽度下通过重排适配，
  不压缩、遮挡或维护平行页面树。
- 中英文、四档字体、Follow System/Light/Dark 使用同一结构且无重叠。
- 图标命令具有本地化 help、accessibility label 和至少 44 点命中；图表与
  拓扑保留键盘、VoiceOver、Reduce Motion 和数值回退。

### R10. Performance And Data Integrity

- 继续消费现有 `AppModel` 领域目录与 Overview 纯投影，不改变 API、DTO、
  领域模型、控制器顺序、发布频率、断开/过期语义或数据可见性。
- 布局状态与实时业务状态隔离；布局变化不能让侧栏、无关页面、静态时间线
  系列或拓扑底图重复重建。
- 首页根只消费窄化的可用性状态、布局版本和窗口编辑状态；实时目录和时间线
  由对应模块观察，不能通过全页可用性扫描放大失效。
- 多窗口可见 domain 需求使用稳定窗口 token 注册、更新和注销；仅在并集
  变化时调整 runtime 的窗口 domain 集，新窗口不能建立第二套网络或刷新
  子系统。全局暂停、日志暂停、baseline publication、runtime 安装和
  generation 替换独立同步完整 demand 快照，不能因 domain 并集未变化而
  被跳过。
- 新进入并集的 domain 只在现有全局暂停、日志暂停和 baseline 门控允许时
  立即 flush；窗口可见性变化不能绕过暂停语义。
- 每个 generation 的完整 demand 快照具有单调 revision；actor 拒绝旧
  revision。runtime 创建时直接接收当前初始快照和 revision，首批 ingest
  不能发生在 demand 初始化之前。
- 个性化持久化不得在滚动或拖动热路径编码。完成编辑时只提交一次，并在退出
  编辑前等待主线程外编码和本地写入；失败保留草稿，不能留下可被切换、关窗
  或应用终止丢失的待写布局。
- 所有控制器覆盖和全局默认共享一个串行合并提交边界。不同窗口同时保存
  不同控制器时也必须基于最新 envelope 合并，不能用旧快照覆盖另一项提交。
- 视觉改造后的 Overview 自动计数和离线基准不得低于
  `07-30-vertical-scroll-jank` 的现有结果。
- 自动验证不连接真实控制器、不访问 9090、不运行核心、不修改系统网络。

## Acceptance Criteria

- [ ] AC1: 默认首屏不再重复完整会话头或四张 KPI 卡，并形成“仪表带 ->
      主遥测 -> 后续内容”的唯一视觉层级。
- [ ] AC2: 主流量与 64-80 点内存轨道保留真实样本、时间窗口、悬停、固定、
      步进、返回实时和辅助功能数值回退。
- [ ] AC3: 三类摘要在宽屏各显示最多三项、在窄屏通过分段控制切换，且
      类别顺序、显隐、1/3/5 项设置和完整页面跳转有效。
- [ ] AC4: 拓扑保留全部连接与链路节点；中性底图、完整路径高亮、固定、
      命中、辅助功能和 Connections 跳转有效。
- [ ] AC5: 网络字段完整显示并按三组对齐；仅组顺序可调，缺失值不伪造。
- [ ] AC6: 五类顶层模块均可排序、选择合法尺寸和显隐；每类最多一个实例且
      至少一个模块可见。仪表带至少一个指标、可见态势摘要至少一个类别。
- [ ] AC7: 三个内置预设只改变布局属性并在草稿中预览，不覆盖内容设置；
      设为默认后取消不会产生任何写入。
- [ ] AC8: 全局默认、控制器覆盖、重置和设为默认在重启后保持；默认变更只
      同步到继承它的控制器，独立覆盖不变；损坏或未来未知布局安全规范化或
      回退；两个窗口并发保存不同控制器时两项都保留。
- [ ] AC9: 取消不写入，完成只提交一次，撤销/重做有效；编辑期间模块业务
      操作不被误触，Cmd-Z/Shift-Cmd-Z 只影响当前窗口草稿，脏草稿不能被
      导航、控制器切换或关窗静默丢弃。
- [ ] AC10: 同一控制器或其继承默认的布局变更同步至其他窗口；已有编辑草稿
      收到明确冲突提示且不被静默覆盖；窗口导航彼此独立，外部控制器切换或
      删除不会丢弃草稿或把它提交到错误控制器。
- [ ] AC11: 冷启动隐藏的遥测/拓扑不创建投影或任务，已显示后再隐藏不增加
      计数；纯重排不增加 timeline projection 或 topology structure/layout
      build count；拓扑尺寸离散变更最多触发一次必要布局；实时帧只更新所属
      模块。
- [ ] AC12: 双窗口分别显示 Overview 与 Logs/Connections 时，发布 domain
      等于两者并集；关闭或导航一个窗口只移除自身需求，且不创建额外网络
      会话、轮询器或流。domain 并集不变时，全局暂停/恢复、日志暂停和
      baseline 状态仍同步到 runtime；新进入并集的 domain 不绕过暂停门控；
      乱序旧快照不能覆盖新 demand，runtime 安装后立即 ingest 也遵守初始
      暂停与 domain 状态。
- [ ] AC13: 360/720/1,180 点、四档字体、中英文和三种外观下无截断、重叠、
      跳动或异常全宽拉伸。
- [ ] AC14: 固定色板对比与所有图标命令 44 点命中通过 HIG 工具；键盘、
      VoiceOver 和 Reduce Motion 人工检查通过。
- [ ] AC15: Swift 构建、测试、源码契约、本地化 JSON、HIG、性能基准和
      `git diff --check` 通过，且未运行真实控制器或旧 runtime smoke。
- [ ] AC16: 当前运行界面截图及主机 SwiftUI Instruments 确认首页层级、
      明暗外观、编辑模式和首次/重复滚动达到目标；若用户未授权启动，则明确
      保留为人工验收项。

## Out Of Scope

- 新控制器能力、API、DTO、业务统计或网络探测。
- Overview 之外十个 destination 的视觉重构。
- 修改固定 graphite/cyan 色板或引入新的品牌主题。
- 通过减少字段、链路、交互或实时更新频率换取简洁。
- 自由画布、模块重叠、多实例、多套命名监控台和任意自定义指标。
- 布局导入、导出、分享和跨设备同步。
