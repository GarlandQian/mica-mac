# 连接页面原生视觉重构

## Goal

把 Connections 从通用数据表外观重构为清晰、快速、具有 Mica 识别度的原生连接工作台。用户应能先判断当前连接负载，再高效扫描、筛选、检查和关闭真实连接，同时始终看清一条连接从来源、规则、策略到目标的完整决策链。

## Confirmed Facts

- Connections 同时浏览控制器报告的活动连接和 Mica 在当前会话保留的已关闭连接；两类数据不得混合或伪装为同一实时状态。
- 当前投影完整保留 ID、主机、源/目标地址、端口、进程、网络、协议、入站、规则、规则载荷、策略链、来源链、上传/下载总量与速率、开始/关闭时间、日志和控制器额外字段。
- 搜索覆盖完整可见数据；只有用户显式选择列排序时才排序展示副本，不能改写控制器数据或来源顺序。
- 选中连接可以跳转到精确规则和策略组；不可解析的目标继续可读，但不得伪造跳转。
- 活动连接支持能力门控的单项、同来源分组和全部关闭；缺少非空控制器 ID 的行只能查看，不能关闭。
- 所有破坏性操作必须使用同窗口确认，并在控制器 ID、会话 generation 或目标集合变化后失效。
- 连接数据最多按 2 Hz 发布。静态字段、指标字段和聚合流量拥有独立 revision；滚动期间不得因实时指标排序反复移动行。
- Mica 使用原生 SwiftUI/macOS 27。页面不得联系测试控制器、制造连接数据、增加普通模态流程或引入无必要的第三方依赖。

## Requirements

### R1. Information hierarchy

- 页面必须让用户在第一视口内辨认连接状态、活动/已关闭范围、结果数量、搜索条件和主要操作。
- 表格上方使用一条紧凑连接概览，展示当前范围内的真实连接数、上传/下载、总流量和主要来源；不得复制 Overview 时间序列或制造缺失统计。
- 主浏览区保持高密度、单滚动轴和稳定行几何；实时速率更新不得导致行高、列宽或页面结构抖动。
- 状态色只表达实时、过期、失败、关闭风险和选择，不使用大面积高饱和填充。

### R2. Connection browser

- 保留一个原生 `Table`，按窗口宽度提供完整列、组合列和单列紧凑布局；任何宽度模式都不能丢失业务字段，完整值进入同窗口详情。
- 主列优先展示目标身份；进程/来源、规则/策略链、上传、下载和时间形成稳定扫描顺序。
- 活动/已关闭切换、搜索、排序、选中、滚动位置和详情状态在当前控制器工作区内保持一致。
- loading、empty、filtered-empty、unsupported、failed、disconnected 和 stale 必须使用统一背景和居中规则，不能出现残留实时数据假象。

### R3. Selected connection

- 选中行后，在同一窗口提供一条可读、可交互的完整决策链：来源或进程 -> 入站 -> 规则 -> 策略/节点 -> 目标。
- 可解析规则和策略组直接跳转到对应页面；链路名称和控制器报告顺序保持原样。
- 详情按身份、路由、传输和附加信息分组；常用字段直接可读，原始额外字段保持完整但不得显示成难以理解的大段机器字符串。
- 关闭连接与关闭同来源组操作靠近选中连接上下文，并继续使用同窗口确认。

### R4. Performance and correctness

- 表格行只读取预计算投影；不得在 row body 中进行全量过滤、排序、聚合或 JSON 格式化。
- 只有变化的连接指标行更新；结构未变化时复用静态搜索文本、身份、规则和链路投影。
- 用户滚动时延后指标排序，但仍更新可见速率；滚动结束后在有界期限内提交最新排序。
- 隐藏 Connections 时不进行昂贵可见投影；重新进入时只接收当前 generation 的最新快照。

### R5. Platform quality

- English、Simplified Chinese、四档界面字号、浅色/深色、Reduce Motion、键盘选择和 VoiceOver 均保持可用。
- 点击目标符合 macOS 指针界面密度，不使用固定 44pt 全局规则。
- 不运行 runtime smoke，不启动 Mica，不访问真实控制器；运行时视觉由用户验收。

## Acceptance Criteria

- [ ] AC1：第一视口清楚区分活动/已关闭、当前状态、结果数量、筛选条件和破坏性操作，且没有重复标题或大面积空白工具栏。
- [ ] AC2：页面始终只有一个原生 `Table` 和一个根滚动所有者；窄/中/宽窗口均无嵌套横向滚动或字段丢失。
- [ ] AC3：选中连接显示完整、按报告顺序排列的交互决策链，并可精确进入对应规则或策略组。
- [ ] AC4：详情完整呈现控制器字段，常用字段可扫描，额外字段结构化展示且不重复已知字段。
- [ ] AC5：单项、分组、全部关闭均经过能力、非空 ID 和 generation 校验；上下文变化后旧确认自动失效。
- [ ] AC6：断线、暂停和 stale 数据不会呈现为实时；无数据、过滤为空和失败状态保持正确居中与统一底色。
- [ ] AC7：2,000 行数据下，实时指标更新不重建全部静态行；滚动期间不因指标排序跳行，相关性能回归测试通过。
- [ ] AC8：源码契约、本地化 JSON、Swift build、连接投影/关闭安全测试、完整 Swift tests 和 `git diff --check` 通过。

## Out of Scope

- 不新增控制器 API、连接采集协议、系统代理或网络修改能力。
- 不改变已关闭连接的保留时长、数量策略或会话生命周期。
- 不把 Overview 的完整连接拓扑复制到 Connections，也不制造时间序列或统计样本。
- 不重构 Logs、Rules、Sources 或其他目的地；只维护必要的精确跳转契约。

## Key Decision

- 采用“紧凑连接概览 + 高密度原生表格”。概览只使用当前连接投影可证明的真实聚合，不重复 Overview 的时间序列、拓扑和网络信息。

## 追加视觉验收：策略组工作区

用户验收连接页后继续检查策略组，确认当前五列节点卡片和整宽字段详情不可接受。本次仅追加策略组展示层修正，不改变控制器、能力或切换语义：

- 节点矩阵在常规宽度保持最多三列，随可用宽度自然降为两列或一列；名称、协议和来源不得被五列密度持续截断。
- 默认节点使用安静的无边框表面；悬停、当前检查项和控制器当前节点分别形成清楚但克制的层级，延迟测试命令不得与每个节点的主要信息争夺注意力。
- 选中节点详情继续位于所属策略组内，但改为可扫描的信息架：概况、传输能力、测试与延迟分栏显示，附加字段默认收起，不输出字段墙。
- Mihomo 普通策略组按 `GLOBAL.all` 中匹配的组名排列，未列出的组保持 `/proxies` 顺序并接在后面，`GLOBAL` 置尾；其他控制器保持报告顺序，组内节点保持各组报告顺序。
- 保持多组同时展开、组内过滤、SMART 报告标签、真实可用性与延迟，以及点击节点后既检查又通过既有安全路径切换的行为。
